# แนวทางทดสอบกล้องและโปรเจกเตอร์ในห้องเรียน

สถานะการทดสอบด้วยมือและกล้องจริง **Not Tested** กรอกผลหลังทดสอบบนอุปกรณ์เป้าหมายจริง

## ตั้งค่าก่อนเก็บผล

- บันทึกรุ่นเครื่อง ระบบปฏิบัติการ เบราว์เซอร์ กล้อง ความละเอียดจอ กราฟิกที่เลือก การประมวลผล GPU หรือ CPU และสภาพแสง
- แบ่งผู้ร่วมทดสอบหลายคนโดยให้มีทั้งมือซ้ายและมือขวา เก็บผลโดยใช้รหัสรอบแทนชื่อนักเรียน
- ใช้โจทย์เดียวกันสำหรับการเปรียบเทียบสภาพแสงหรือระยะ เช่น `x − 3 = 5` ใช้ +3 ฝั่งหนึ่งและ +1 สามครั้งอีกฝั่ง
- จดจำนวนเหตุการณ์เท่านั้น ภาพบันทึกเพื่อวัดเวลาหากจำเป็นควรถ่ายหน้าจอและมือโดยไม่เก็บใบหน้าหรือข้อมูลระบุตัวตน

## ลำดับทดลอง

1. ทดสอบแต่ละมือที่ระยะประมาณ 40, 65 และ 90 ซม. ทั้งแสงธรรมชาติและแสงในห้อง
2. ทดลองหนีบเร็ว หนีบช้า การถือค้าง การลากจากคลังไปยังทั้งจานซ้ายและขวา และการปล่อยนอกจาน
3. ให้คนเดินผ่านหลังผู้เล่นหรือมีมือคนอื่นในภาพ ตรวจว่ามือที่เลือกยังควบคุมอยู่
4. เอามือออกจากภาพระหว่างลาก แล้วนำกลับทั้งท่ายังหนีบและท่าคลาย ตรวจว่าไม่มีการบันทึกคำสั่งจากการหายไป
5. จำลองการถอดกล้องและกลับเข้าแอป เปลี่ยนเป็นเมาส์ แล้วทดสอบการกลับไปใช้กล้อง
6. เล่นต่อเนื่อง 30 นาที สลับเต็มหน้าจอและออกจากแอป ตรวจว่าแถบกล้องปิดตามสตรีม และเก็บ FPS กับ memory timeline ของเบราว์เซอร์

| ตัวชี้วัด | เป้าหมาย | ผลที่บันทึก |
| --- | --- | --- |
| หยิบและวางตามเจตนาที่ถูกบันทึก ÷ เหตุการณ์ตั้งใจ | ≥ 95% | |
| คำสั่งที่เกิดขึ้นโดยไม่ตั้งใจ ÷ เหตุการณ์ทดลองทั้งหมด | < 1% | |
| p95 จากปล่อยถึงเริ่มเคลื่อนในอุปกรณ์จริง | ≤ 150 ms | |
| Rendering ในช่วงเล่นและใช้กล้อง | ≥ 30 FPS | |
| ความแม่นยำของสมการ | ผ่านกรณีบังคับทั้งหมด | |
| เล่นต่อเนื่องและคืนทรัพยากร | ไม่มี Crash หรือทรัพยากรเพิ่มผิดปกติ | |

ถ้าใช้การบันทึกหน้าจอเพื่อวัดเวลา ให้รายงานอัตราเฟรมของการบันทึกด้วย เช่น 120 FPS จะมีความละเอียดตามช่วงเฟรมประมาณ 8.3 ms เก็บอย่างน้อย 30 การวางสำหรับ p95 และใช้สูตร nearest rank ของตัวอย่างที่เรียงจากน้อยไปมาก
